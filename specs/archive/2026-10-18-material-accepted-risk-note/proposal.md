# Note only material accepted risks, once

## Problem

The user reports a Security note that restates a residual risk they had already
accepted, for a marginal case: an unlisted directory-service account sharing a
private primary group. The core records every accepted exposure or risk in the
note without a materiality condition, and the accepted-risk case expects the
note to reappear in a continuation with unchanged scope.

## Goal

Record an accepted risk in the Security note only when it meets the existing
Review and Report materiality test, and only once, with the delivery that
implements it. Source: the user's request that the note appear only for real
risks and approval of the proposed requirements in this conversation on
2026-10-18. Record NOTE-001 and NOTE-002 in this directory and update the
readable requirements catalog, the paired model case, and current measurements.

## Non-goals

No version, release, installation, loader, or module changes. No change to the
confirmation duty, explicit overrides, or renewed confirmation for a materially
changed action, exposure, or scope. Material risks the delivery creates or
worsens without acceptance keep their note.

## Compatibility

A confirmed, material trade-off still produces exactly one note in the delivery
that implements it. Later replies of the same scope no longer repeat it. An
accepted risk that fails the materiality test produces no note.
